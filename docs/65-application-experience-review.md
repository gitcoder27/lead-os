# LeadOS: application experience review

Reviewed 2026-10-02 against `3e0fb83`. Audience: engineering managers and project leads.

## Verdict

LeadOS has a credible daily-work foundation: capture, personal planning, delegation, team visibility, standup, private notes and weekly decisions connect through shared tasks. It is useful for a practiced manager, but first-use discoverability, mobile density and several trust gaps prevent an equally easy experience for everyone.

**Recommendation: finish a bounded reliability pass, then upgrade Team and the person drawer, then complete weekly reporting.** Team remains the next substantial screen upgrade; reliability fixes should precede it.

## Evidence and limits

- **Visual:** inspected the actual frontend with synthetic, read-only API fixtures: Today, Tasks, Team/person drawer, Work and Notes at 1440 × 900; Today and Tasks at 390 × 844. Fixture writes were refused. Screenshots establish layout, not real data correctness or production speed.
- **Code:** traced routing, capture, view membership, mutations, person follow-ups, Jira edits, onboarding, settings, Copilot, My Day, Standup and 1:1s. Checked earlier findings against current implementation.
- **Validation:** 505 tests in 15 selected frontend suites and 96 tests in five backend suites passed; `npm run typecheck` and `npm run build:check` passed. Frontend tests emitted jsdom `window.scrollTo` warnings. These checks do not establish complete accessibility or usability.
- Production, runtime databases and Jira were untouched. No user interviews, screen-reader testing, dark-theme browser audit or large-data performance measurements were performed. Recommendations below are judgments, not measured user outcomes.

## What already works well

- Solo setup can start without Jira or developer logins. Navigation adapts to configured sources.
- Tasks provides a coherent Inbox → plan → execute/wait → close lifecycle, saved views and bulk actions.
- Today retains unfinished commitments through wrap-up; recent fixes address failed-action rollback, timezone handling and incomplete-source reporting.
- Standup has guided person/task navigation, draft handling and improved switching. Manager identity now includes the linked roster record.
- Notes already uses CodeMirror, recoverable drafts, merge handling and task/source links; the older “bare textarea” finding is obsolete.
- Shared dialogs, persistent error toasts, keyboard help and confirmation-gated Copilot writes provide a sound interaction foundation.

## Proposed sequence and additions

1. **Trust pass:** R1–R4, then the existing Tasks interaction fixes. Reconcile the stale parts of docs/61 before execution; TS-01 is already done.
2. **Team upgrade:** R6, with R7's shared-shell cleanup. First slice: complete person commitments plus blocker context and one linked next action, within the existing drawer.
3. **Reporting:** R9. This is the strongest already-specified functional addition.
4. **Jira execution:** R10, staged around real triage use rather than a broad project-management rewrite.
5. **Evaluate later:** R12; recurring manager commitments if repeated weekly recapture is demonstrated; a milestone/release lens if existing labels/saved views cannot answer delivery questions. Reuse Jira facts where available. These are proposals, not implementation authorization.

Avoid extra top-level pages, decorative dashboards, employee productivity scores and a second dependency/task model. Keep personal Notes private; person context should use explicit links and manager-private records. Preserve solo mode and manager/developer visibility boundaries.

## How to judge the upgrade

Run a short usability session with a first-time and a practiced manager: capture a task, build a plan, delegate/check a promise, resolve a blocker, prepare a 1:1 and produce a weekly update. Record completion, misclicks, navigation steps and confidence in saved state.

Target: identify the person needing attention and record the next action within 30 seconds; produce a reviewed weekly update within 10 minutes. Treat these as proposed goals. Verify keyboard-only completion, 390px layout, 200% zoom, both themes, save failures/retries, timezone boundaries and read-only history. Measure production-build performance on representative large fixtures before choosing pagination or virtualization.
